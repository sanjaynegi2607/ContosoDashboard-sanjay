# Data Model: Document Upload and Management

## Document

Represents a user-uploaded business file.

| Field | Type | Rules |
|---|---|---|
| `DocumentId` | integer | Primary key; generated by SQLite. |
| `Title` | text | Required; trimmed; user-facing search field. |
| `Description` | text, nullable | Optional description. |
| `Category` | text | Required; stored as text for existing model consistency. |
| `FileName` | text | Sanitized original display name; never used as the storage path. |
| `StoredFilePath` | text | Internal path returned by `IFileStorageService`; outside `wwwroot`. |
| `FileType` | text | Normalized extension without the leading period. |
| `FileSizeBytes` | integer | Required; maximum 25 MB. |
| `UploadedByUserId` | integer | Required owner; restricted foreign key to `User`. |
| `ProjectId` | integer, nullable | Optional association; set null when the project is removed. |
| `UploadedAtUtc` | datetime | Required creation timestamp. |
| `UpdatedAtUtc` | datetime | Updated on metadata, replacement, and deletion changes. |
| `IsDeleted` | boolean | Excluded from user queries after authorized deletion. |
| `ScanStatus` | text | Required lifecycle value: `PendingScan`, `Clean`, `Quarantined`, or `ScanFailed`. |
| `ScanContentHash` | text, nullable | Hash of the scanned file content used to reject stale queue messages and make retries idempotent. |
| `ScanUpdatedAtUtc` | datetime, nullable | Last scan-status transition timestamp. |
| `ScanError` | text, nullable | User-safe failure description; must not contain scanner internals or file contents. |

**Relationships**: Many documents may belong to one project; many documents may be uploaded by one user; one document may have many shares and audit records.

## DocumentShare

Represents explicit access granted to a user.

| Field | Type | Rules |
|---|---|---|
| `DocumentShareId` | integer | Primary key. |
| `DocumentId` | integer | Required cascade relationship to `Document`. |
| `UserId` | integer | Required recipient; restricted relationship to `User`. |
| `SharedByUserId` | integer | Required granting user; restricted relationship to `User`. |
| `SharedAtUtc` | datetime | Required creation timestamp. |
| `IsActive` | boolean | Active shares grant access; inactive shares do not. |

An active share must not duplicate the same document and recipient. The owner cannot share a document with themselves.

## UploadAuditLog

Records upload, download, delete, and share events.

| Field | Type | Rules |
|---|---|---|
| `UploadAuditLogId` | integer | Primary key. |
| `DocumentId` | integer, nullable | Set null when document metadata is removed; current design retains soft-deleted rows. |
| `UserId` | integer | Required actor. |
| `ActionType` | text | One of `Upload`, `Download`, `Delete`, or `Share`. |
| `ActionDateUtc` | datetime | Required UTC event timestamp. |
| `Details` | text, nullable | Human-readable event context. |

## Access Rules

A document is accessible when it is not deleted and the requesting user is one of:

1. The uploader/owner.
2. A member of the associated project, when a project association exists.
3. A recipient of an active explicit share.

The same predicate must govern list, detail, download, preview, and shared-document operations. Delete is restricted to the owner or associated project manager. Sharing is restricted to the owner unless the specification is amended.

## State Transitions

```text
New upload -> Stored -> Available
Stored -> Upload failed -> No metadata record and no orphan file
Available -> Metadata updated -> Available
Available -> File replaced -> PendingScan with new storage path
Available -> Authorized delete -> Deleted metadata state and removed physical file
Available -> Share created -> Available plus active recipient access and notification
PendingScan -> Clean -> Available for download/preview
PendingScan -> Quarantined -> Blocked from download/preview
PendingScan -> ScanFailed -> Blocked from download/preview, retry or operator action required
```

New uploads and replacements MUST begin in `PendingScan`. Only `Clean` documents may be downloaded or previewed. A queue worker may transition a document only when the message content hash matches the current stored file hash.

## Indexes and Integrity

- Index document uploader, project, and category fields for common filters.
- Index active shares by document, recipient, and active state.
- Use restricted user foreign keys to preserve audit and ownership integrity.
- Use cascade deletion for share rows when a document row is removed.
- Use set-null project and audit document relationships where the existing context defines that behavior.
